# Buyer and bounded value hypothesis

The intended user is the maintainer reviewing schema/data upgrades for an embedded SQLite application, such as a local billing, inventory or offline desktop product. A migration that succeeds on an empty schema can still fail on duplicate historical values, silently change application reads, or have a rollback that restores columns without their old contents. The output is a review artifact for a migration pull request, not an automated production deployment approval.

[Atlas migration lint](https://atlasgo.io/versioned/lint) documents migration analysis and development-database execution. It deserves credit for established migration-safety workflows, destructive/incompatibility policies and much wider dialect support. [SQLite's backup API](https://www.sqlite.org/backup.html) provides real database copying; [authorizer](https://www.sqlite.org/c3ref/set_authorizer.html) provides prepare-time access decisions. These primary pages were checked on 2026-10-03. We claim no market-first algorithm or omission from competitors based on documentation silence.

The executable comparison uses a transparent regex review shortcut and same-engine empty-schema rehearsal with the same SQL/contracts/rollback, not an incumbent. Seven deterministic synthetic policies include safe and adverse outcomes and a contract blind spot. Populated rehearsal matches 7/7 expected declared decisions, regex 2/7 and empty-schema rehearsal 4/7. These are designed cases, not population accuracy or a claim about Atlas. Ablations remove actual data contracts and rollback to expose their contribution. Run `python benchmarks/contrast.py` for measured local elapsed times and decisions. Timings are hardware/interpreter-dependent, include subprocess startup and do not establish a speed advantage.

Economic scenario, explicitly hypothetical: if a reviewer spends 20 minutes manually setting up/inspecting a local clone and this workflow takes 5 minutes to configure plus measured execution time, it could save about 15 reviewer minutes per applicable migration. At an assumed internal labor cost of $60/hour, that is about $15 per review before maintenance and integration costs. Neither time assumption was measured with users; no incident probability, avoided-loss dollar estimate, customers or revenue is asserted. Main advantage demonstrated here is changed decisions with inspectable evidence, not proven willingness to pay.

Adoption path: install a wheel, supply a closed test database and SQL/JSON contracts, gate CI on CLI exit 2, and keep the artifact alongside the migration. SQLite tooling remains the execution engine and existing migration systems remain responsible for deployment. Support boundary is Python 3.11+, ordinary standalone SQLite databases under declared limits; other dialects, live databases, host security and incomplete business contracts remain outside scope.

为什么做：迁移评审容易把“结构能改回来”误当成“数据能恢复”，也容易遗漏历史数据中的重复值与消费者查询变化。本项目把这些检查放入可复现的本地流程，并明确呈现缺失业务契约时仍会接受的反例。商业价值是可测试的评审省时与风险识别机制；真实采纳率、收入与支付意愿尚未知。
