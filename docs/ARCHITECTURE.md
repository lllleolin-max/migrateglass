# Execution model

The parent validates the file and limits, hashes the source, starts a fresh Python worker with JSON over stdin and imposes a wall timeout. The worker opens `file:...?mode=ro&immutable=1`, uses SQLite backup into a fresh in-memory connection, then closes the source connection. It enables foreign keys, disables trusted schema and extensions, stores temporary objects in memory, installs limits and a progress callback.

State transitions: source audit → before snapshot/contracts → transactional migration → after snapshot/contracts and row-loss decision → optional transactional rollback → restoration comparison → report. Any failed migration statement rolls back that transaction and rejects. The source is never a destination. Each user statement has an authorizer at prepare time; cached statements are disabled. A separate read-only authorizer policy is used for all contract queries. User transaction control is denied so implicit commits cannot puncture the engine transaction. The parent verifies source SHA-256 after success, SQL failure or worker timeout.

Snapshot equality uses ordered schema SQL records and per-table typed-row multisets. Text, blobs, real hex representations, integers and nulls remain distinct; duplicates remain counted; scan order is immaterial. Reports include digests/counts, not rows. Schema equality is deliberately strict textual SQLite schema equality, not a cross-dialect semantic proof. No rollback supplied means `NOT_REQUESTED`, not verified reversibility. Successful rollback is applied to the migrated clone, never a fresh baseline clone.

Limits cover source bytes, clone page growth, individual SQLite value length, script bytes/statement count, fetched rows, SQL VM steps and child wall time. VM progress is sampled every 100 instructions; `vm_steps_upper_estimate` is a conservative sample estimate. The process timeout includes interpreter startup. Hashing and parent invocation validation are outside that timeout. Clone page limits do not bound all SQLite temporary allocations or the operating system's RSS. An interrupted worker is killed; its in-memory clone is discarded.

For R rows and S schema objects, row hashing is O(R) and multiset sorting O(R log R); retained result and digest state is O(R). Backup cost is proportional to source pages. Each phase adds audit and query work; the reported VM count is cumulative. Whole-database snapshots intentionally favor small embedded databases over warehouse scale.

Statements are split at semicolon candidates only when `sqlite3.complete_statement` returns true. Trigger `BEGIN ... END` and semicolons in quoted strings/comments remain together. This is not a complete SQL AST or a lexical safety filter. Authorizer callbacks, actual SQLite constraints and query execution decide acceptance. Large/pathological parser workloads are bounded by script size and the parent wall timeout.

The source must be externally quiescent and already checkpointed/closed. Existing `-wal`, `-shm`, `-journal` companions are rejected. Immutable mode assumes no concurrent writer; SHA verification detects changed bytes after the run but does not provide locking, atomic pathname acquisition or malicious-host isolation. `ACCEPT` means only the observed fixture, SQLite version, supported subset and declared contracts passed.
